# 00. Game Constitution

이 문서는 프로젝트의 최상위 개발 헌장이다. AI Agent, 개발자, 기획자는 아래 원칙을 임의로 변경할 수 없다. 변경이 필요하면 먼저 이 문서와 관련 문서를 수정하고, 변경 사유를 `09_CHANGELOG.md`에 기록해야 한다.

## 절대 핵심 원칙

| ID | 원칙 | 구현 기준 | 변경 가능 여부 |
|---|---|---|---|
| GC-001 | 모바일 세로형 캐주얼 액션 게임 | 기준 해상도 1080x1920, 한 손 조작 우선 | 불가 |
| GC-002 | 상단 아이가 똥을 발사하고 하단 플레이어가 맞춘다 | 아이는 상단 25%, 플레이어는 하단 25%, 액션 영역은 중앙 50% | 불가 |
| GC-003 | 아이 컨디션이 똥 종류와 발사 패턴에 영향을 준다 | 컨디션별 확률 테이블은 JSON에서 로드 | 불가 |
| GC-004 | 타격/슬링샷 액션의 즉각적인 손맛이 핵심 재미다 | 입력 후 100ms 이내 시각/사운드 피드백 | 불가 |
| GC-005 | 모든 밸런스 수치는 데이터 기반으로 관리한다 | 속도, 점수, 체력, 보상, 가격은 코드 하드코딩 금지 | 불가 |
| GC-006 | 기존 기능 삭제 금지 | 삭제 전 TODO, GDD, TDD, CHANGELOG에 사유 기록 | 불가 |
| GC-007 | 코어 루프를 방해하는 BM 금지 | 광고/과금은 선택형, 실패를 강제로 유도하지 않음 | 불가 |

## Core Loop

```text
스테이지 진입
-> 아이 컨디션 결정
-> 컨디션에 따른 똥 발사
-> 플레이어 조준/타격
-> 명중, 회피, 피격 판정
-> 점수/콤보/재화 획득
-> 웨이브 진행
-> 보스 또는 클리어
-> 보상 지급
-> 성장/스킨/수집품 해금
-> 다음 스테이지 도전
```

## 플레이 세션 기준

| 항목 | 기준 |
|---|---|
| 1판 길이 | 일반 스테이지 60~120초, 보스 스테이지 90~150초 |
| 조작 | 드래그 조준, 릴리즈 발사 또는 탭 타격 |
| 실패 조건 | 라이프 0, 제한 시간 초과, 보스 패턴 실패 |
| 성공 조건 | 목표 점수 달성, 모든 웨이브 클리어, 보스 체력 0 |
| 보상 | 코인, 경험치, 수집 조각, 광고 보너스 |

## AI Agent 개발 규칙

1. 기능 구현 전 관련 문서를 먼저 확인한다.
2. 기획 변경이 필요하면 코드보다 문서를 먼저 수정한다.
3. 기존 로직을 단순화한다는 이유로 시스템을 삭제하지 않는다.
4. 밸런스 수치는 `assets/data/*.json` 또는 `src/config/*.json`에 둔다.
5. 임시 테스트 수치라도 코드에 직접 박지 않는다.
6. 변경 후 `08_TODO.md` 체크 상태와 `09_CHANGELOG.md`를 갱신한다.
7. 에셋 교체 시 화면 위치, pivot, collision radius, hitbox key를 유지한다.
8. 저장 데이터 구조 변경 시 마이그레이션 버전을 추가한다.

## 임의 삭제 금지 규칙

| 대상 | 금지 행동 | 허용 조건 |
|---|---|---|
| Manager 클래스 | 사용처가 적다는 이유로 삭제 | TDD 개정, 테스트 통과, CHANGELOG 기록 |
| JSON 필드 | 현재 코드에서 안 쓴다는 이유로 삭제 | deprecated 표시 후 1개 버전 유지 |
| 에셋 | 새 이미지로 교체하며 기존 파일 제거 | 참조 검색 후 대체 경로 반영 |
| UI 버튼 | 플로우가 복잡하다는 이유로 제거 | UX 문서와 QA 체크리스트 갱신 |
| 밸런스 항목 | 기본값으로 통합 | Balance Book 개정 후 가능 |

## 문서 우선 수정 원칙

기능 추가 순서는 다음을 따른다.

| 순서 | 작업 | 산출물 |
|---|---|---|
| 1 | 기획 영향 확인 | `01_GDD.md` 수정 |
| 2 | 기술 영향 확인 | `02_TDD.md` 수정 |
| 3 | AI 개발 규칙 확인 | `03_AI_DEVELOPMENT_SPEC.md` 준수 |
| 4 | 밸런스 정의 | `05_BALANCE_BOOK.md` 및 JSON 수정 |
| 5 | TODO 등록 | `08_TODO.md` |
| 6 | 구현 | 코드, 에셋, 데이터 |
| 7 | 검증 | 테스트 결과 기록 |
| 8 | 변경 기록 | `09_CHANGELOG.md` |

## JSON 기반 밸런스 원칙

모든 런타임 밸런스는 JSON으로 관리한다. 코드에는 JSON key와 fallback 정책만 둔다.

```json
{
  "schemaVersion": 1,
  "poopTypes": {
    "normal": {
      "speed": 520,
      "radius": 42,
      "score": 100,
      "difficulty": 1,
      "asset": "poop_normal_01"
    }
  },
  "conditionRates": {
    "good": {
      "normal": 45,
      "fast": 20,
      "gold": 10,
      "heavy": 15,
      "split": 10
    }
  }
}
```

## 데이터 검증 규칙

| 검증 항목 | 기준 |
|---|---|
| 확률 합계 | 컨디션별 똥 등장 확률 합계는 100 |
| 음수 금지 | 속도, 점수, 체력, 가격은 0 이상 |
| ID 안정성 | 출시 후 ID 변경 금지, 표시명만 변경 가능 |
| 누락 대응 | 필수 key 누락 시 개발 빌드는 오류, 릴리즈 빌드는 기본값 로드 |
| 버전 관리 | JSON마다 `schemaVersion` 필수 |
